# Home weather and energy follow-up

PR1 (KEA-344) depends on the tablet-memory repair in PR343. PR2 adds procedural weather decoration on top; neither implies deployment or physical acceptance on all devices.

The reported iPhone weather outage was not reproduced on the laptop: exact Auckland geocoding and forecast requests both returned valid HTTP200 responses on 4 October2026. The repair removes Auckland's unnecessary geocoding round trip using the provider's city-centre coordinates; other regions validate NZ geocoding and cache their result. URL construction uses encoded parameters without platform URL mutation. Timeout, provider errors, stale observations and aborted requests remain failures, never invented temperatures. The weather chip supports retry, restores validated last-known regional data and labels it when stale or a refresh fails. The 3D scene only receives fresh conditions. Weather is regional modelled Open-Meteo data, not customer GPS or energy telemetry. Source: [Open-Meteo forecast](https://open-meteo.com/en/docs) and [geocoding](https://open-meteo.com/en/docs/geocoding-api).

EV cable animation requires fresh mapped charging power above10W. No EV sensor, zero/invalid/stale watts and illustrative preview alone keep it off. This does not claim physical plugged-in status: the integration currently maps power sensors, not an EV connection entity. Daily energy/ownership cannot establish charging. Home poll results expire after60seconds; sensor readings already have their own timestamp/validation gate. Opposing grid and battery readings animate their signed net magnitude; equal values stop. Solar stays green, battery blue, grid orange and EV cyan. Wider, more opaque saturated pulses retain those hues; source pipe/cable routes and geometry stay unchanged.

When any live path has a valid reading (including zero), missing paths remain off; illustrative preview is not mixed into that measured scene.

## Weather worlds (KEA-346, second PR)

The original72 stars were beyond the Home camera frustum. A bounded420-point world-space shell now includes visible upper-sky stars across reveal and all manual orbit extremes; a projected fade keeps the lower image quiet. One short seeded meteor trail starts every4seconds of active scene time, lasts0.95seconds, and chooses a varied upper-sky position at event start. It then remains anchored in world space while the user rotates. Clear/partly-cloudy night has stars; precipitation/fog and very heavy cloud suppress them. Missing/stale weather can show decorative clock-only night stars without claiming clear regional conditions.

Daylight uses blue/teal with sparse moving cloud wisps even in clear conditions. Overcast, rain/drizzle/storm, fog and snow have separate palettes. Rain has72 falling slanted streaks, snow64 gently drifting points; sunny days include three tiny birds, and warmer NZ spring/summer/autumn days three fading pastel butterflies. Night has up to12 softly appearing/disappearing green-gold fireflies outside precipitation/fog. All share the existing foreground-only30fps GSAP demand clock; reduced motion keeps static scenery and disables meteor/wing/particle movement. No independent timers, particle textures, React object spawning on ticks, or edits to original model/Bloub, native binary loader or render budgets.

The first physical iPhone follow-up caught an invalid calibration: counting nearby vertices had accepted wall regions as glass and omitted the upper floor. Textured elevations and indexed-triangle rays instead locate front glass at z0.467–0.480, recessed door glass at z0.188 and central glass at z0.178. Seven inset pane regions now exclude timber/frames geometrically and include upper glazing with a sloping roof cutoff. A brightness gate was removed because linear conversion rejected almost-black upper panes. Three source apertures lack glass triangles; bounded warm matte backings fill those openings behind their frame planes. Warm amber frosted shading has a vertical light falloff. This is illustrative interior lighting, not measured lamp status, and needs renewed physical appearance acceptance.

The iPhone test also reported missing land/sky and reflective-looking background artifacts. The sky never wrote depth, so a depth-occlusion root cause is not established. Cloud wisps now only occupy the upper viewport, at lower spatial frequency/contrast, with depth testing disabled for the background. Their pattern remains world-anchored while a projected fade suits the downward-facing isometric camera, whose viewport does not see an astronomical upper hemisphere. A finite matte weather-coloured ground disk (radius1.7) sits below every original model/pavement vertex (y−0.46 versus source minimum−0.42225); upper-sky rays miss it across manual orbit extremes. Snow uses a pale ground and rainy/night scenes muted tones. No reflective materials are used. Screenshot/device retest remains the authority for resolving that reported appearance.

Local validation also compiles10 actual shader stages (including modified Three basic stages) using installed Three chunks and glslangValidator with an identity output-conversion stub; this verifies syntax, not native GPU rendering. Browser preview navigation/focus timed out twice, so no browser visual pass is claimed. Strict typing remains enabled; explicit TS-extension imports are allowed in this no-emit Expo project so freshness logic is shared with Node strip-types regressions.
