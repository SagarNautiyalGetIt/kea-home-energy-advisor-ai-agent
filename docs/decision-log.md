# Decision log

One line per non-obvious choice, with the date and the reason. Half the MIT report
writes itself out of this file, and future-you stops re-deciding settled things.

Substantial decisions get their own ADR in `docs/adr/`; this is for everything smaller.

| Date | Decision | Why |
|---|---|---|
| 2026-08-17 | Sprint 2 runs fully local, no AWS | Removes cloud setup from the critical path; Bedrock migration is ADR-0004's job |
| 2026-08-17 | SQLite over Postgres | Five seeded households; removes a container from a stack that must run on a laptop |
| 2026-08-17 | Structural integers ≤ 12 exempt from the number-checker | "Two things to note" is prose, not a claim; unit-bearing tokens are always claims |
| 2026-08-17 | Verify before streaming, not during | Cannot put an unverified figure on screen; revisit sentence-level verification on faster hardware |
| 2026-08-17 | Ported the 31 measured July values into `tests/data/july_2026_daily.json` | Ran `measure-july-chart.py` from the Iris Vault; the analytics are now validated against real data instead of shaped fixtures |
| 2026-08-17 | `COMPARISON_BASELINE = 7.06 kWh/day` | Derived from Genesis's own "37% more than similar homes": 300.0 kWh / 1.37 / 31. External benchmark, never derived from the household |
| 2026-08-17 | Renamed the headline fact to `overshoot_annual_cost` | The published $290/yr is the **whole overshoot** annualised (81 kWh/mo x $0.30 x 12), not the sustained portion alone — see research/analysis.md line 83 |
| 2026-08-17 | `SPIKE_THRESHOLD = 1.8` | **Open question, not settled.** 1.8x reproduces the published method (11 Jul alone, 10.4%, $2.52). 1.5x also flags Fri 10 Jul and the spike share jumps to 16.4%. The looser detector is arguably more correct but weakens "the spike is only 11%". Team must decide which method we defend |
| 2026-08-18 | Two-speed models: adopt the shape, skip the second model | The fast/slow pattern assumes a slow reasoning step to hide. ADR-0002 already moved reasoning out of the model — layer 1 is arithmetic and runs in ~1 ms — so the only delay is narration. Layer 0 knows the intent in ~0 ms, so a pre-synthesised acknowledgement is faster than any model, cannot fabricate, and loads no second set of weights competing for the same memory bandwidth. Revisit for barge-in (Sprint 3) |
| 2026-08-18 | Demo machine = MacBook Pro M4 Pro / 48 GB | Benchmarked both Macs: 2.15× the mini on 4B models, 2.42× on 12B. Mac mini is a genuine backup provided we ship a 4B model |
| 2026-08-18 | Primary model candidate = `qwen3:4b` | 141 ms to first word vs 322 ms for `gemma3:4b` at identical throughput, consistent across both machines. For a phone channel, first-word latency beats raw speed. Apache-2.0 licence is a bonus. **Speed decision only** — Day 6 golden set decides quality |
| 2026-08-18 | PostgreSQL, not SQLite (ADR-0006) | Time-series data, `numeric` for money (float drift is the one bug this product cannot survive), `timestamptz` for NZ daylight saving, and a connection-string path to RDS |
| 2026-08-18 | Local git only — never push this repo anywhere | Standing instruction from Akash. The internship is competitive (other teams bid for the same scenario) and the vaults hold client-adjacent and personal material. `.github/workflows/ci.yml` stays as a file but only runs if pushed, which won't happen. Verified: no remote configured on any vault or repo |
| 2026-08-18 | Illustrative Low Fixed Charge rate 0.34 → 0.36 /kWh | At 0.34 the break-even sat at 30 kWh/day, so LFC looked cheaper for almost every household — the tariff advice would have been wrong for most of the demo. 0.36 puts break-even at 20 kWh/day, matching NZ's LFC regulation (~8,000 kWh/yr). Pinned by a test |
| 2026-08-18 | Demo households defined once, in `app/analytics/fixtures.py` | They had been defined twice — the API served H-A..H-E while the seeder wrote H-JUL..H-TARIFF, so every chat request 404'd. `seed.py` now imports the definition |
| 2026-08-18 | `UsageWindow.median_kwh` is a `cached_property` | The median was recomputed once per reading inside a comprehension in `sustained_overshoot_per_day`, making it quadratic. 26 µs at 31 daily totals, **57 ms at one month of half-hourly intervals** — which is exactly what KEA-32's seeding produces. Now 188 µs. Frozen dataclasses cache fine; `cached_property` writes to `__dict__` directly |
| 2026-08-18 | `get_provider()` is `lru_cache`d | It was building a new provider — and therefore a new `httpx.AsyncClient` and connection pool — on every request, and `last_usage` was per-request state the cost projection (KEA-58) could never aggregate. One provider, one pool, closed in the app lifespan |
| 2026-08-18 | `Settings` fields use `default_factory`, not bare `os.getenv` | A bare `os.getenv` in a dataclass body evaluates **once, at class creation**, so every later `Settings()` returned the environment as it was at import. The Day 6 bake-off (KEA-47) sets `KEA_OLLAMA_MODEL` per run — it would have benchmarked the 4B model three times and recorded three results |
| 2026-08-18 | `/chat/stream` validates `customer_id` before the response starts | It returned **500 with a half-open SSE stream** where `/chat` returned 404 for the same input, because the KeyError was raised after `StreamingResponse` had committed a 200 |
| 2026-08-18 | Empty `FactBundle`s carry caveats | `compare_to_last_year` routes but has no layer 1 path (KEA-69), so the model got an empty bundle with **no constraints at all**. This is the one case layer 3 cannot cover: *"your usage was higher than last winter"* has no numeric token, so the number-checker passes it. Caveats are the only guard until the analytics land |
| 2026-08-18 | Sentence splitting by regex, not `text.split(". ")` | The old split broke `"…, e.g. roughly $24"` into a chunk ending `"e.g."` and then appended a second full stop. ADR-0003 has voice speaking sentence one while sentence two generates, so a bad boundary is **audible** |
| 2026-08-18 | Retry names the rejected tokens | Attempt 2 re-sent a byte-identical prompt at temperature 0.2, which mostly reproduces the identical failure — the model had no way to know what was wrong. It now sees which figures were refused. **Whether this lifts the pass rate is a KEA-46 golden-set question, not a matter of taste** — measure it before claiming it |
| 2026-08-18 | Sprint 2 board card IDs renumbered | KEA-35/36/37/38 each named two different cards; KEA-38 was simultaneously done (ADR-0006) and not started (weather normalisation). Day 3 → KEA-64–66, Day 4 → KEA-67–70. Mapping table at the top of `board.md` |
| 2026-08-24 | Adopted the operational columns from Harvey's `app` schema, kept our verification spine | The `elt` branch models `app.conversation` / `app.conversation_message` with `outcome`, `was_escalated`, `hardship_detected`, `message_count`, `retain_until`, `model_version`, `latency_ms` and `cited_sources` — all things we lacked and none of them backfillable. What it does **not** have is a verification table, and *"N answers, 0 fabricated figures"* has nowhere else to live. Merged both rather than choosing: his operational columns, our `fact_bundle` / `verification` / `token_usage` / `escalation` |
| 2026-08-24 | `retain_until` deliberately has no default | Harvey's call, adopted verbatim. This table holds payment-difficulty disclosures; an unset retention date should be visible and fixable rather than silently meaning "forever" |
| 2026-08-24 | Persistence is opt-in via `KEA_PERSIST=1`, and `/health` reports which recorder is live | Requiring PostgreSQL for `/chat` would stop four frontend people running the backend without Docker. The risk of the opt-out is rehearsing all afternoon and finding the evidence tables empty, so the mode is disclosed on `/health` rather than being silent |
| 2026-08-24 | An evidence-write failure never fails the answer | A customer asking why their bill is high gets their answer even if the recorder cannot reach the database. Logged at ERROR, because a silent recorder is worse than none — it produces a count that is confidently wrong |
| 2026-08-24 | `conversation_id` is checked against the customer before it is appended to | It arrives from the client. Without the ownership check, an id from one customer could append turns to another customer's transcript — and these transcripts contain hardship disclosures |
| 2026-08-24 | The golden set found two router bugs, including demo line 2 | *"Wasn't that just the cold snap?"* routed to `out_of_scope` — the router had no weather phrasing at all, so the scripted question could not reach weather attribution. Found by KEA-46 on its first run, which is the argument for the golden set existing |
| 2026-08-24 | Repository seam: async I/O loads a `UsageContext`, layer 1 stays pure and synchronous | Making the analytics async would spread `await` through pure arithmetic and force the golden set to need an event loop. Splitting `await repo.context(id)` from `bundle_from_context(intent, ctx)` keeps one bundle builder serving the database, the fixtures and the golden set — the alternative is two builders that drift until the demo disagrees with the tests. Pinned by a parity test over every intent × household |
| 2026-08-24 | Daily aggregation groups in `Pacific/Auckland`, not the session timezone | `date_trunc('day', ...)` on a `timestamptz` uses the session timezone, which is UTC in a container. At UTC+12 that pushes every evening reading into the following day — silently reshaping the exact evening peak the whole analysis is about |
| 2026-08-24 | A household with no benchmark raises rather than falling back | The comparison baseline must never be derived from the household itself; that bug once inflated the spike's apparent share from 11% to 71%. There is no safe default to substitute, so it fails loudly |
| 2026-08-24 | One flag (`KEA_PERSIST`) drives both reads and writes | Two flags would allow a state where the API writes conversations to PostgreSQL while serving analytics from a Python file — coherent-looking and wrong. `/health` reports both `data_source` and `recording` |
| 2026-08-25 | Bill-shock compares against **comparable homes**, never the customer's own history | There is no billing history in the seeded data — a single cycle. "More than you usually pay" is therefore unknowable, and asserting it would be the exact fabrication the product exists to prevent. The caveat is explicit and pinned by a test |
| 2026-08-25 | Two thresholds required to trigger: ≥15% **and** ≥$20 | A percentage alone fires constantly on small bills; a dollar floor alone never fires on large ones. H-SPIKE proves the pair is needed — it clears 30% and is held back only by the dollar floor |
| 2026-08-25 | Early-cycle warnings are hedged, not suppressed | Testing showed H-SPIKE and H-DROP both trigger around day 7 on evidence that later settles. Neither is a bug: on day 7 those households really are heading somewhere expensive. Suppressing them would defeat a *prevention* agent, so below 10 elapsed days the bundle carries an explicit instruction not to present the figure as what they will pay |
| 2026-08-25 | The bill-shock warning is a GET, not a chat intent | Every other endpoint answers a question somebody asked. A warning that only appears if you think to ask for it is not a warning — it has to reach the customer before the bill does, so the dashboard polls it |
| 2026-08-25 | Dashboard figures now come from the API | The metric row and the shock card were hardcoded literals — including a "29% higher than your usual range" that was both fabricated and a claim we cannot make. An invented "Projected Monthly Bill" sat on the same screen as a computed one |
| 2026-08-25 | First real model run: 9/10 prompts verified first attempt on `gemma3:4b` | 25 figures checked, 0 fabricated reached the customer. The single failure was `compare_to_last_year` (KEA-69), where the empty bundle let the model invent a year — rejected, regenerated, then correctly fell back to the template. Confirms the layer-3 design works against a real model |
| 2026-08-26 | One owner per namespace: `alembic upgrade head` creates `app.*`, `make data-load` creates `kea.*` | Migration 0003 was creating its own copy of the marts, which would have collided with the `elt` fixtures and, worse, left two authorities for one set of tables. Alembic no longer touches the marts; `data/design/kea_serving_schema.sql` is their definition of record and `app/db/marts.py` maps them read-only — models with no migration, which is what "the app holds SELECT on `kea.*`" looks like in code |
| 2026-08-26 | `app.alert` is Harvey's `kea.alert`, relocated and given a tier | The access rules give the app SELECT-only on `kea.*`, and this row is written the instant a warning fires. It has to live in a schema we can write to |
| 2026-08-26 | Alert idempotency is a unique constraint on `(account_ref, kind, period, tier)`, not a Python check | The dashboard polls, and check-then-insert races itself the moment there are two workers. Without the constraint the first rehearsal emails the customer on every poll. Verified against real PostgreSQL: three polls, one email |
| 2026-08-26 | Alert tiers stack rather than replace | A tier-3 customer gets the call **and** the email. A failed call leaves no record, and the written notice is what the Consumer Care Obligations expect us to be able to produce |
| 2026-08-26 | Tier escalation needs either the dollar gate or the percent gate, unlike the trigger which needs both | The percent-only path is the one that matters: a low user 75% over is a real emergency for that household even when the dollar figure is modest, and low-fixed-charge customers are the shape this is aimed at. A rising trend deliberately does **not** raise the tier — "getting worse" is not "already expensive" |
| 2026-08-26 | Hardship suppresses the send but still records the tier | The fact that we knew and chose not to make contact belongs on the record, not absent from it |
| 2026-08-26 | Email defaults to a file backend writing `.eml` to `var/outbox`; SMTP refuses to start without a password | No credential, no network, and it cannot hang the warning on conference wifi. Refusing to start beats degrading silently to "no mail", which is indistinguishable from working |
| 2026-08-26 | No model composes any part of an alert | It leaves the building unprompted with nobody reviewing it first, so every figure comes straight off the assessment. This is the one output with no human and no second pass between us and the customer |
| 2026-08-26 | Narration model sized to the machine's unified memory: 27B on the 48 GB M4, 12B on the 16 GB backup, 4B elsewhere | One hardcoded `gemma3:4b` served the smallest box on the team and wasted the largest — and the largest is the one the pitch is delivered on. Keyed on unified memory because that is what decides whether a model fits; generation on Apple Silicon is bandwidth-bound. Non-Apple hardware keeps the floor, since system RAM says nothing about a discrete GPU. Unreadable memory falls to the **floor, never the ceiling**: an oversized model does not error, it swaps, and a 40-second answer is indistinguishable from a hang on the night |
| 2026-08-26 | `app/pipeline.py` is the only function that turns a question into prose | ADR-0003 said "voice cannot produce an answer chat wouldn't"; this makes it structural instead of aspirational. `/chat`, `/chat/stream` and `/api/voice/stream` all call it, and `test_voice.py` asserts both channels return identical text for the same question |
| 2026-08-26 | `/health` reports voice `ready` separately from `enabled` | `enabled` only says somebody set the flag; `ready` says the binaries and weights are on disk. Offering a microphone that cannot work is worse than not offering one |
| 2026-08-26 | `GGML_METAL`, not the deprecated `WHISPER_METAL` | whisper.cpp v1.7.4 accepts the old name only through a deprecation shim that warns and forwards. Depending on a forwarding macro for the one flag that makes the demo machine fast is how you end up on stage with a CPU build and nothing in the output explaining it |
| 2026-08-26 | `alert.channel` records the channel that actually carried it, not the intended one | It was writing `tier=2 channel=sms status=delivered` when there is no SMS gateway and the email did the work. A row claiming a delivery that never happened is precisely the flattering-but-false record this project refuses everywhere else. `facts` now carries the intended ladder and which rungs are unwired |
| 2026-08-27 | `app/auth.py` is explicitly **not** authentication, and says so at length | No user table, no hashing, no sessions, plaintext constants — gated off by default behind `KEA_DEMO_LOGINS` so a deployment that forgets the flag returns 503 instead of an open door. Safe only because every account behind it is synthetic, and the file has to make that impossible to misread |
| 2026-08-27 | Baseline for the mart accounts is the mean daily use of the **other** seeded accounts | Not an invention, and deliberately not derived from the household itself. It is a real cohort, reproducible from the same tables, and stateable out loud — which matters, because a benchmark nobody can source is the softest number on screen |
| 2026-08-27 | Analytics windows are trimmed to the most recent complete month | Handing month-shaped analytics 397 days produced a peak reported as "day 351" and a period label whose stray "31" the number-checker correctly rejected. It was right: that 31 is not a fact |
| 2026-08-27 | `peak_usage` compares against the **median**, not the mean | One big spike drags a 31-day mean up far enough to make itself look ordinary, which is precisely what the customer is asking about |
| 2026-08-27 | `time_of_day` deliberately carries no figures at all | The half-hourly data behind the demo households is one fixed 48-interval shape scaled by each day's total, so every household's "hourly curve" is the same synthetic curve. **Naming a peak hour off that would pass layer 3 and still be a fabrication.** It says plainly that we can show which day but not which hour, and offers the day instead |
| 2026-08-27 | `Fact.day_of_period` carries a `days` unit so a day number is checked as a claim | A bare integer under `STRUCTURAL_INT_MAX` would have been waved through as prose structure, and a wrong day is a wrong answer even when the arithmetic is right. Pinned by golden case V-109 |
| 2026-08-27 | `--reload` removed from the API launch config | A reload restarts the worker and takes every open WebSocket with it. Voice is the only long-lived connection in the app, so it is the only thing that notices, and it surfaces as a bare 1006 that looks identical to "the server was never there". Hot reload is worth having, but not at the cost of the one feature that cannot survive a restart |
| 2026-08-27 | The assistant is named Sparky; Kea Energy stays the retailer | Sparky speaks and is addressed; the footer, news, onboarding, tariff and alert emails remain the company's. Untouched deliberately: the `KEA_*` env vars, the package name, and the `kea.*` schema — that last one is the data platform's namespace and renaming it would break every ELT fixture |
| 2026-08-28 | The recorder provisions a bare identity anchor with `ON CONFLICT`, not a caught `IntegrityError` | In PostgreSQL a statement that raises **aborts the transaction**, so catching the error would poison the session and lose the very turn it was trying to save. `/api/households` filters the anchors out, or every mart account would appear twice in the picker |
| 2026-08-28 | `.env` is loaded by fifteen lines using `setdefault`, not a `python-dotenv` dependency | Nothing had ever read `.env`, so the README's `cp .env.example .env` did nothing and the API came up on fixtures with no recording, no logins and no voice — silently. `setdefault` only, so a real exported variable always wins; otherwise launch configs and CI would be overridden by a file |
| 2026-08-28 | **Documented, not fixed:** the live schema has no `ON DELETE CASCADE` on the conversation spine | `kea_app_schema.sql` documents it; migration 0001 created the FKs without it and 0003 only moved the tables with `SET SCHEMA`. The design file is aspirational there. **Deletes must be child-first** until the two are reconciled |
