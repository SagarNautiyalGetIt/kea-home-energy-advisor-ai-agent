# Decision log

One line per non-obvious choice, with the date and the reason. Half the MIT report
writes itself out of this file, and future-you stops re-deciding settled things.

Substantial decisions get their own ADR in `docs/adr/`; this is for everything smaller.

| Date | Decision | Why |
|---|---|---|
| 2026-08-17 | Sprint 2 runs fully local, no AWS | Removes cloud setup from the critical path; Bedrock migration is ADR-0004's job |
| 2026-08-17 | SQLite over Postgres | Five seeded households; removes a container from a stack that must run on a laptop |
| 2026-08-17 | Structural integers ≤ 12 exempt from the number-checker | "Two things to note" is prose, not a claim; unit-bearing tokens are always claims |
| 2026-08-17 | Verify before streaming, not during | Cannot put an unverified figure on screen; revisit sentence-level verification on faster hardware |
| 2026-08-17 | Ported the 31 measured July values into `tests/data/july_2026_daily.json` | Ran `measure-july-chart.py` from the Iris Vault; the analytics are now validated against real data instead of shaped fixtures |
| 2026-08-17 | `COMPARISON_BASELINE = 7.06 kWh/day` | Derived from Genesis's own "37% more than similar homes": 300.0 kWh / 1.37 / 31. External benchmark, never derived from the household |
| 2026-08-17 | Renamed the headline fact to `overshoot_annual_cost` | The published $290/yr is the **whole overshoot** annualised (81 kWh/mo x $0.30 x 12), not the sustained portion alone — see research/analysis.md line 83 |
| 2026-08-17 | `SPIKE_THRESHOLD = 1.8` | **Open question, not settled.** 1.8x reproduces the published method (11 Jul alone, 10.4%, $2.52). 1.5x also flags Fri 10 Jul and the spike share jumps to 16.4%. The looser detector is arguably more correct but weakens "the spike is only 11%". Team must decide which method we defend |
| 2026-08-18 | Two-speed models: adopt the shape, skip the second model | The fast/slow pattern assumes a slow reasoning step to hide. ADR-0002 already moved reasoning out of the model — layer 1 is arithmetic and runs in ~1 ms — so the only delay is narration. Layer 0 knows the intent in ~0 ms, so a pre-synthesised acknowledgement is faster than any model, cannot fabricate, and loads no second set of weights competing for the same memory bandwidth. Revisit for barge-in (Sprint 3) |
| 2026-08-18 | Demo machine = MacBook Pro M4 Pro / 48 GB | Benchmarked both Macs: 2.15× the mini on 4B models, 2.42× on 12B. Mac mini is a genuine backup provided we ship a 4B model |
| 2026-08-18 | Primary model candidate = `qwen3:4b` | 141 ms to first word vs 322 ms for `gemma3:4b` at identical throughput, consistent across both machines. For a phone channel, first-word latency beats raw speed. Apache-2.0 licence is a bonus. **Speed decision only** — Day 6 golden set decides quality |
| 2026-08-18 | PostgreSQL, not SQLite (ADR-0006) | Time-series data, `numeric` for money (float drift is the one bug this product cannot survive), `timestamptz` for NZ daylight saving, and a connection-string path to RDS |
| 2026-08-18 | Local git only — never push this repo anywhere | Standing instruction from Akash. The internship is competitive (other teams bid for the same scenario) and the vaults hold client-adjacent and personal material. `.github/workflows/ci.yml` stays as a file but only runs if pushed, which won't happen. Verified: no remote configured on any vault or repo |
| 2026-08-18 | Illustrative Low Fixed Charge rate 0.34 → 0.36 /kWh | At 0.34 the break-even sat at 30 kWh/day, so LFC looked cheaper for almost every household — the tariff advice would have been wrong for most of the demo. 0.36 puts break-even at 20 kWh/day, matching NZ's LFC regulation (~8,000 kWh/yr). Pinned by a test |
| 2026-08-18 | Demo households defined once, in `app/analytics/fixtures.py` | They had been defined twice — the API served H-A..H-E while the seeder wrote H-JUL..H-TARIFF, so every chat request 404'd. `seed.py` now imports the definition |
| 2026-08-18 | `UsageWindow.median_kwh` is a `cached_property` | The median was recomputed once per reading inside a comprehension in `sustained_overshoot_per_day`, making it quadratic. 26 µs at 31 daily totals, **57 ms at one month of half-hourly intervals** — which is exactly what KEA-32's seeding produces. Now 188 µs. Frozen dataclasses cache fine; `cached_property` writes to `__dict__` directly |
| 2026-08-18 | `get_provider()` is `lru_cache`d | It was building a new provider — and therefore a new `httpx.AsyncClient` and connection pool — on every request, and `last_usage` was per-request state the cost projection (KEA-58) could never aggregate. One provider, one pool, closed in the app lifespan |
| 2026-08-18 | `Settings` fields use `default_factory`, not bare `os.getenv` | A bare `os.getenv` in a dataclass body evaluates **once, at class creation**, so every later `Settings()` returned the environment as it was at import. The Day 6 bake-off (KEA-47) sets `KEA_OLLAMA_MODEL` per run — it would have benchmarked the 4B model three times and recorded three results |
| 2026-08-18 | `/chat/stream` validates `customer_id` before the response starts | It returned **500 with a half-open SSE stream** where `/chat` returned 404 for the same input, because the KeyError was raised after `StreamingResponse` had committed a 200 |
| 2026-08-18 | Empty `FactBundle`s carry caveats | `compare_to_last_year` routes but has no layer 1 path (KEA-69), so the model got an empty bundle with **no constraints at all**. This is the one case layer 3 cannot cover: *"your usage was higher than last winter"* has no numeric token, so the number-checker passes it. Caveats are the only guard until the analytics land |
| 2026-08-18 | Sentence splitting by regex, not `text.split(". ")` | The old split broke `"…, e.g. roughly $24"` into a chunk ending `"e.g."` and then appended a second full stop. ADR-0003 has voice speaking sentence one while sentence two generates, so a bad boundary is **audible** |
| 2026-08-18 | Retry names the rejected tokens | Attempt 2 re-sent a byte-identical prompt at temperature 0.2, which mostly reproduces the identical failure — the model had no way to know what was wrong. It now sees which figures were refused. **Whether this lifts the pass rate is a KEA-46 golden-set question, not a matter of taste** — measure it before claiming it |
| 2026-08-18 | Sprint 2 board card IDs renumbered | KEA-35/36/37/38 each named two different cards; KEA-38 was simultaneously done (ADR-0006) and not started (weather normalisation). Day 3 → KEA-64–66, Day 4 → KEA-67–70. Mapping table at the top of `board.md` |
| 2026-08-24 | Adopted the operational columns from Harvey's `app` schema, kept our verification spine | The `elt` branch models `app.conversation` / `app.conversation_message` with `outcome`, `was_escalated`, `hardship_detected`, `message_count`, `retain_until`, `model_version`, `latency_ms` and `cited_sources` — all things we lacked and none of them backfillable. What it does **not** have is a verification table, and *"N answers, 0 fabricated figures"* has nowhere else to live. Merged both rather than choosing: his operational columns, our `fact_bundle` / `verification` / `token_usage` / `escalation` |
| 2026-08-24 | `retain_until` deliberately has no default | Harvey's call, adopted verbatim. This table holds payment-difficulty disclosures; an unset retention date should be visible and fixable rather than silently meaning "forever" |
| 2026-08-24 | Persistence is opt-in via `KEA_PERSIST=1`, and `/health` reports which recorder is live | Requiring PostgreSQL for `/chat` would stop four frontend people running the backend without Docker. The risk of the opt-out is rehearsing all afternoon and finding the evidence tables empty, so the mode is disclosed on `/health` rather than being silent |
| 2026-08-24 | An evidence-write failure never fails the answer | A customer asking why their bill is high gets their answer even if the recorder cannot reach the database. Logged at ERROR, because a silent recorder is worse than none — it produces a count that is confidently wrong |
| 2026-08-24 | `conversation_id` is checked against the customer before it is appended to | It arrives from the client. Without the ownership check, an id from one customer could append turns to another customer's transcript — and these transcripts contain hardship disclosures |
| 2026-08-24 | The golden set found two router bugs, including demo line 2 | *"Wasn't that just the cold snap?"* routed to `out_of_scope` — the router had no weather phrasing at all, so the scripted question could not reach weather attribution. Found by KEA-46 on its first run, which is the argument for the golden set existing |
| 2026-08-24 | Repository seam: async I/O loads a `UsageContext`, layer 1 stays pure and synchronous | Making the analytics async would spread `await` through pure arithmetic and force the golden set to need an event loop. Splitting `await repo.context(id)` from `bundle_from_context(intent, ctx)` keeps one bundle builder serving the database, the fixtures and the golden set — the alternative is two builders that drift until the demo disagrees with the tests. Pinned by a parity test over every intent × household |
| 2026-08-24 | Daily aggregation groups in `Pacific/Auckland`, not the session timezone | `date_trunc('day', ...)` on a `timestamptz` uses the session timezone, which is UTC in a container. At UTC+12 that pushes every evening reading into the following day — silently reshaping the exact evening peak the whole analysis is about |
| 2026-08-24 | A household with no benchmark raises rather than falling back | The comparison baseline must never be derived from the household itself; that bug once inflated the spike's apparent share from 11% to 71%. There is no safe default to substitute, so it fails loudly |
| 2026-08-24 | One flag (`KEA_PERSIST`) drives both reads and writes | Two flags would allow a state where the API writes conversations to PostgreSQL while serving analytics from a Python file — coherent-looking and wrong. `/health` reports both `data_source` and `recording` |
